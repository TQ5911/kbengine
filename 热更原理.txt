其中refreshData()的定义如下
def refreshData(includeModules=None):
    INFO_MSG('refreshData with args:', includeModules)
    try:
        _refreshData(includeModules)
    finally:
        _RELOADED_MODULES.clear()

# 判断模块是否为配置文件
def _isData(module):
    # __file__属性来确定是否有对应的物理文件(.py或者库模块)
    # 且路径中包含'data'字符串(即是data配置文件目录的文件)
    # 且模块中包含datas属性
    return hasattr(module, '__file__') and 'data' in module.__file__ and hasattr(module, 'datas')

默认不传任何参数是全部配置更新,否则更新对应的配置
_refreshData如下
sys.modules 会存储当前服务已经加载(导入)过的所有模块信息,即通过import导入的模块

def _refreshData(includeModules):
    globalAttrCacheList = {
        'gacha_gachaPool': ('expiredDrawCardPoolCache',),
    }
    clearGlobalAttrCacheList = []

    import sys
    for moduleName, module in sys.modules.items():
        if includeModules:
            if moduleName not in includeModules:
                continue
        # 获取模块文件的路径
        modulePath = getattr(module, '__file__', '')
        # 判断是否为配置文件
        if modulePath and _isData(module):
            DEBUG_MSG('_refreshData::reload({})'.format(moduleName))
            # 通过importlib.reload来重新动态加载该模块,并且直接更新sys.modules 中对应的模块对象
            new_module = importlib.reload(module)
            # 缓存一下
            # add to reloaded modules
            _RELOADED_MODULES[moduleName] = new_module
            if moduleName in globalAttrCacheList:
                for attrName in globalAttrCacheList[moduleName]:
                    clearGlobalAttrCacheList.append(getattr(sys.modules['gameglobal'], attrName, None))
    # 清理全局变量
    DEBUG_MSG('_refreshData::clearDataCache', clearGlobalAttrCacheList)
    gameglobal.clearDataCache(clearGlobalAttrCacheList)

    # 需要清理缓存的模块
    # clear ai controller poll when refresh ai_ai data cfg
    cacheList = [
        ('aiControllerPool', 'pool', 'clearAllPool'),
        ('combatSkill', 'SkillBase', 'clearAllCache'),
        ('buff', 'Buff', 'clearAllCache'),
        ('dataUtils', 'getTaskData', 'cache_clear'),
    ]
    # 设置一个清理缓存的回调
    KBEngine.addTimer(0.1, 0.1, functools.partial(clearCacheInTick, cacheList))
    # 这个暂时不看
    for moduleName, module in sys.modules.items():
        for r_name, r_module in _RELOADED_MODULES.items():
            _module = getattr(module, r_name, None)
            if _module and _module is not r_module:
                DEBUG_MSG('_refreshData::reReference({}, {})'.format(
                    moduleName, r_name))
                setattr(module, r_name, r_module)

























线上代码热更以及分支操作流程
服务端线上热更方法：
1. 安装astor模块
    sudo apt-get install python3-astor

2. 执行getHotReload.py脚本
	cd Server/kbeLinux/kbengine/assets/hotReload
2.1 对于类方法参数格式为：component module class method
      python3 ./genhotfix.py cellapp iCrusade ICrusade _enterTeamCrusadeDungeon

2.2 对于模块方法，参数格式为：component module method
     python3 ./genhotfix.py baseapp dataUtils getRaidConstDataValue

3.在游戏中 GM执行$hotreload命令， 游戏内的代码就会热更到最新

cd Server/kbeLinux/kbengine/assets

./cmd_hotReload.sh

注：1.每次运行脚本工具 会在 hotReload.py 中增加一个 要热更新的函数，原有的其他函数会保留。 
      2.使用GM命令的的时候，会热更 hotReload.py 内的 refreshCell() 或者 refreshBase() 中的 所有函数
      3.提供三个GM命令：
	
	$hotreload:同时在cellapp和baseapp上执行
	
	$hotreloadCell: 在各个cellapp上执行hotReload.refreshCell()函数
	
	$hotreloadBase: 在各个baseapp上执行hotReload.refreshBase()函数

线上分支操作流程：

1. 功能代码修复后，提交到trunk分支
2. 合并分支，merge到online本地分支
3. 用上面的服务端线上热更方法，在online本地分支制作hotreload, 位置：Server/kbeLinux/kbengine/assets/scripts/server_common/hotreload.py
4.在online本地分支测试hotreload功能生效
5.提交hotreload和修复的代码到svn远程online分支
6.找对应的功能测试同学，在online分支验证：1. hotreload代码，2. 功能代码
7.走发布流程发布到线上
